# Reflexiones · Claude Code in Action

Este documento recoge mis ideas, aprendizajes y cambios de mentalidad durante el curso.

No pretende resumir el contenido, sino dejar constancia de cómo ha evolucionado mi forma de trabajar con Claude Code.

---

# Reflexión 1 · Claude deja de ser un asistente

Antes veía Claude Code como una herramienta para responder preguntas o ayudarme a escribir código.

Después de este curso empiezo a verlo como un compañero de trabajo capaz de ejecutar tareas largas si soy capaz de definir correctamente el objetivo, las reglas y los mecanismos de verificación.

Mi trabajo cambia.

Cada vez consiste menos en escribir código y más en diseñar sistemas para que Claude pueda trabajar de forma autónoma.

---

# Reflexión 2 · Planificar vale más que corregir

Uno de los cambios de mentalidad más importantes ha sido entender el valor del Modo Plan.

Invertir unos minutos revisando un plan puede ahorrar horas corrigiendo una mala implementación.

Esta idea no solo aplica a Claude Code.

También quiero aplicarla a mis propios proyectos y a mi forma de trabajar.

---

# Reflexión 3 · El contexto es un recurso

Nunca había pensado que el contexto fuese algo que hubiese que administrar.

Ahora entiendo por qué existen herramientas como Compact, Rewind o Goal.

No se trata de hablar más con Claude.

Se trata de mantener únicamente el contexto realmente útil.

---

# Reflexión 4 · CLAUDE.md no es un contrato

Antes pensaba que cuanto más completo fuese un CLAUDE.md, mejor.

Ahora entiendo justo lo contrario.

Cada regla compite por la atención del modelo.

Prefiero un archivo pequeño, claro y específico que uno enorme lleno de reglas que terminarán siendo ignoradas.

---

# Reflexión 5 · Automatizar no significa confiar ciegamente

Una de las ideas que más me ha gustado del curso es que la confianza no proviene del modelo.

Proviene del sistema.

Tests automáticos, Hooks, Skills de verificación, revisiones independientes...

Todo está diseñado para que la calidad no dependa de recordar hacer comprobaciones manuales.

---

# Reflexión 6 · Pensar como un arquitecto

Empiezo a darme cuenta de que aprender IA no consiste únicamente en aprender modelos.

También consiste en diseñar procesos.

Cada vez que aparezca una tarea repetitiva quiero hacerme una pregunta:

> ¿Cómo podría hacer para no volver a realizar esta tarea manualmente?

Creo que esta será una forma de pensar muy útil tanto para mis propios proyectos como para futuros clientes.

---

# Reflexión 7 · Aplicación a mis proyectos

Mientras hacía este curso he pensado varias veces en proyectos que quiero desarrollar.

Me imagino utilizando Claude para:

- revisar automáticamente mis repositorios;
- generar documentación;
- comprobar cambios antes de hacer commits;
- automatizar tareas repetitivas;
- construir agentes especializados para pequeños negocios.

Eso hace que el curso tenga mucho más sentido para mí, porque no lo veo como teoría, sino como herramientas que probablemente utilizaré en pocos meses.

---

# Qué quiero empezar a aplicar desde hoy

- Planificar antes de ejecutar tareas grandes.
- Mantener mi CLAUDE.md limpio y sencillo.
- Pensar siempre si una tarea repetitiva puede automatizarse.
- Verificar el trabajo antes de confiar en él.
- Construir sistemas antes que depender de prompts aislados.

---

# Mi mayor aprendizaje

Este curso no me ha enseñado simplemente a utilizar Claude Code.

Me ha enseñado una nueva forma de trabajar.

La idea más importante que me llevo es que el objetivo no es hacer que Claude responda mejor.

El objetivo es construir un entorno donde Claude pueda trabajar de forma autónoma, segura y fiable.
