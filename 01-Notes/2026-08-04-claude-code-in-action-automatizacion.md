# Claude Code in Action: de asistente a compañero de trabajo

## Qué hice

  `Practical Cases.md`, `README.md`).
- Rellené el `README.md` y `Key Concepts.md` del curso.
- Escribí `Reflections.md` con 7 reflexiones completas sobre cómo cambió mi forma de trabajar con
  Claude Code durante el curso.

## Ideas clave

- **Claude deja de ser un asistente.** Antes lo veía como una herramienta para responder preguntas o
  ayudarme a escribir código; después de este curso empiezo a verlo como un compañero de trabajo
  capaz de ejecutar tareas largas si soy capaz de definir bien el objetivo, las reglas y la verificación.
- **Planificar vale más que corregir.** Invertir unos minutos revisando un plan puede ahorrar horas
  corrigiendo una mala implementación — quiero aplicar esta idea también a mis propios proyectos.
- **El contexto es un recurso.** Nunca había pensado que el contexto fuese algo que hubiese que
  administrar. No se trata de hablar más con Claude, sino de mantener únicamente el contexto
  realmente útil.
- **CLAUDE.md no es un contrato.** Antes pensaba que cuanto más completo, mejor; ahora entiendo lo
  contrario — cada regla compite por la atención del modelo, y prefiero un archivo pequeño y
  específico a uno enorme que termine siendo ignorado.
- **Automatizar no significa confiar ciegamente.** La confianza no viene del modelo, viene del sistema:
  tests automáticos, Hooks, Skills de verificación, revisiones independientes.
- **Pensar como un arquitecto.** Aprender IA no consiste únicamente en aprender modelos, también en
  diseñar procesos — cada tarea repetitiva es una pregunta: ¿cómo evitar volver a hacerla a mano?

También aprendí, a nivel de conceptos del curso: los tres niveles de instrucciones (CLAUDE.md guía,
Skills automatizan procedimientos, Hooks garantizan comportamientos obligatorios), los distintos modos
de permisos, la importancia de la verificación cuanto más autónoma es una ejecución, y los niveles de
automatización (Rutinas, modo Headless, modo Bare, Agent SDK).

## Qué quiero empezar a aplicar

- Planificar antes de ejecutar tareas grandes.
- Mantener mi CLAUDE.md limpio y sencillo.
- Pensar siempre si una tarea repetitiva puede automatizarse.
- Verificar el trabajo antes de confiar en él.
- Construir sistemas antes que depender de prompts aislados.

Mientras hacía este curso pensé varias veces en proyectos que quiero desarrollar: revisar
automáticamente mis repositorios, generar documentación, comprobar cambios antes de hacer commits,
automatizar tareas repetitivas, construir agentes especializados para pequeños negocios.

## Próximos pasos

Mi mayor aprendizaje de este día: el objetivo no es hacer que Claude responda mejor, sino construir un
entorno donde Claude pueda trabajar de forma autónoma, segura y fiable.
